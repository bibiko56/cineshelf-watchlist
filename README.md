## How It Works

CineShelf is a static web application that runs entirely in the user's browser. When a user opens the site, the web server (hosted in the cloud) sends the four HTML pages, `styles.css`, and the two JavaScript files, `auth.js` and `app.js`, to the browser in response to a simple GET request. After that, the browser handles all of the work itself, because the system has no backend, API, or database. The user first signs in or registers on `index.html`. There, `auth.js` checks the credentials against the accounts stored in `localStorage`, creates a session, and redirects the user according to their role. Regular users go to `dashboard.html`, where `app.js` reads and writes their personal watchlist, applies the search and filters, and updates episode progress. On `stats.html`, `app.js` computes the viewing insights from the same stored data and lets the user export or import a JSON backup. Admins can also open `admin.html`, where they manage registered users and publish featured picks that regular users can add to their own lists with one click. The role guard in `auth.js` runs on every page and sends anyone who is not logged in, or not an admin, away from the pages they should not see. The `localStorage` component works as the data layer, keeping the users, the current session, each user's watchlist, and the featured picks, so the HTML pages, the JavaScript logic, and the stored data work together inside the browser. Finally, the GitHub repository sits outside the running application as version control, where developers push and pull code changes before the updated static files are deployed to the cloud host.
